# check-versions

Python CLI для аудита версий PHP и Nginx во всех запущенных Docker-контейнерах.
Перебирает контейнеры через `docker ps`, проверяет наличие и версию бинарников,
выводит три списка для каждого: **найден** (с версией), **не найден**,
**ошибка проверки**.

Создан после выхода CVE-2026-109618/109619 (PHP RCE, CVSS 9.2), чтобы быстро
найти уязвимые версии во всех контейнерах на хосте.

## Требования

- Python 3.10+ (используются `str | None`, `list[tuple[str, str]]`)
- Docker в `PATH` (скрипт вызывает `docker ps` и `docker exec`)
- Права на `docker exec` (обычно достаточно быть в группе `docker`)

## Использование

```bash
chmod +x check-php-nginx-versions.py
./check-php-nginx-versions.py
```

С JSON-выводом (для CI):

```bash
./check-php-nginx-versions.py --json
```

Без `chmod`:

```bash
python3 check-php-nginx-versions.py
```

## Пример вывода

```text
===== PHP =====

--- PHP: найден ---
  blog-prod-app-1                          PHP 8.2.35 (cli) (built: Nov  5 2026 07:29:09) (NTS)
  gogpt-worker                             PHP 8.3.36 (cli) (built: Nov  5 2026 07:26:27) (NTS)
  ...

--- PHP: не найден ---
  (нет)

--- PHP: ошибка проверки ---
  blog-prod-blog-webserver-1
  blog-prod-redis-1
  ...

===== Nginx =====

--- Nginx: найден ---
  blog-prod-blog-webserver-1               nginx version: nginx/1.31.8
  ...

--- Nginx: не найден ---
  (нет)

--- Nginx: ошибка проверки ---
  blog-prod-app-1
  ...
```

## Что означают секции

| Секция | Значение |
| --- | --- |
| найден | Бинарник есть в `PATH`, версия получена |
| не найден | `command -v` вернул пусто — бинарника нет в `PATH` |
| ошибка проверки | `docker exec` упал: контейнер в Restarting, нет `sh` или нет прав |

Цвета включаются автоматически, только если вывод идёт в терминал
(`sys.stdout.isatty()`). При перенаправлении в файл или pipe цвета отключаются,
чтобы не засорять логи.

## Безопасные версии (на ноябрь 2026)

| Ветка | Минимальная безопасная версия | Почему |
| --- | --- | --- |
| PHP 8.2 | 8.2.35 | закрывает CVE-2026-109618/109619 |
| PHP 8.3 | 8.3.36 | закрывает CVE-2026-109618/109619 |
| PHP 8.4 | 8.4.27 | закрывает CVE-2026-109618/109619 |
| PHP 8.5 | 8.5.12 | закрывает CVE-2026-109618/109619 |
| Nginx | 1.30.6 (stable) / 1.31.8 (mainline) | серия уязвимостей 2026 года |

Если скрипт показывает версию ниже — контейнер уязвим, требуется пересборка
образа с безопасным базовым тегом.

## Что скрипт не проверяет

- **OpenResty** (nginxproxymanager) — отдельная ветка, свои security-адвизори.
  Скрипт покажет версию `openresty/...`, но не классифицирует её как
  «безопасную/уязвимую».
- **PHP в legacy-контейнерах** (например, PHP 5.6) — скрипт покажет версию,
  но решение о миграции/изоляции принимается отдельно.
- **Зависимости приложения** (composer/npm-пакеты) — это зона разработчика,
  не инфраструктуры.
